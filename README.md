# Fandoogh Manager

افزونهٔ پایهٔ مدیریت فروشگاه فندوق برای WordPress و WooCommerce است. رابط مدیریت به‌صورت یک PWA بدون وابستگی runtime ارائه می‌شود و اتصال واقعی آن از API داخلی افزونه انجام می‌شود.

## توسعه و بررسی

پیش‌نیازها: Node.js 20 یا جدیدتر و PHP برای بررسی syntax فایل‌های backend.

```bash
npm ci
npx playwright install chromium webkit
npm run lint
npm run test:coupons
npm run test:product-categories
npm run test:app-assets
npm run test:service-worker
npm run test:admin
npm run test:analytics
npm run test:e2e:chromium
npm run test:e2e:webkit
```

`npm run test:e2e:preview` (و aliasهای `test:e2e` و `test:e2e:all`) همهٔ پروژه‌ها را اجرا می‌کند. تست‌های چیدمان برنامه را از سرور استاتیک `tools/static-server.js` و با `?preview=1` باز می‌کنند. تست‌های گردش کار کوپن پاسخ‌های HTTP را در مرورگر شبیه‌سازی می‌کنند تا نمایش نتیجهٔ ثبت، صفحه‌بندی و خطاها بررسی شود. `test:coupons` نیز قرارداد backend را با مدل‌های آزمایشی درون حافظه بررسی می‌کند. این آزمون‌ها جایگزین تست integration روی WordPress و WooCommerce واقعی نیستند.

## ساخت بستهٔ نصب

### پنل مدیریت و گزارش مالی — ۱٫۳٫۸

منوی Fandoogh Manager اکنون یک پیشخوان با هشت تب دارد: پیشخوان، ظاهر، رسانه و فونت، گزارش مالی، دسترسی کاربران، نشست‌ها و امنیت، اتصال و وب‌اپ، رهگیری سفارش. هر فرم فقط کلیدهای مجاز همان تب را با آخرین تنظیمات ذخیره‌شده ادغام می‌کند؛ خاموش‌کردن یک چک‌باکس در یک تب، تنظیمات تب دیگر را تغییر نمی‌دهد. آدرس قدیمی «تنظیمات» همچنان باز می‌شود.

برای گزارش مالی، ابتدا گزینه را در تب گزارش مالی ذخیره کنید. حساب باید مجوز مدیریت ووکامرس یا تنظیمات وردپرس و دسترسی تحلیل در افزونه داشته باشد. اگر کد اتصال/نشست پیش از فعال‌شدن گزارش صادر شده، در «اتصال و وب‌اپ» کد جدید بسازید، از وب‌اپ خارج شوید و دوباره با آن وارد شوید. افزایش خودکار مجوز نشست قدیمی عمداً انجام نمی‌شود. اکنون این وضعیت به‌جای ناپدیدکردن بخش، پیام روشن دارد؛ شکست دریافت دادهٔ ووکامرس نیز با گزارش خالی اشتباه گرفته نمی‌شود.

`test:admin` ذخیرهٔ مستقل تب‌ها و خروجی واقعی توابع PHP را با بدل‌های وردپرس بررسی می‌کند. تست مرورگری پنل، HTML واقعی همین توابع را در قاب سبک‌شدهٔ آزمایشی وردپرس بررسی می‌کند؛ جایگزین تأیید ظاهر/ذخیره روی سایت واقعی نیست. `test:analytics` و تست مرورگری گزارش مالی هم با دادهٔ آزمایشی اجرا می‌شوند.

از نسخهٔ ۱٫۳٫۶، فایل‌های عمومی پوسته با پارامتر `fandoogh_manager_asset` روی مسیر `/manager/` تحویل می‌شوند؛ بنابراین میزبان‌هایی که مسیرهای مجازی `.css` و `.js` را مستقیماً در Nginx با ۴۰۴ پاسخ می‌دهند، نیازی به قانون ویژه برای این فایل‌ها ندارند. مسیر خود `/manager/` باید همچنان در وردپرس قابل دسترسی باشد. مسیرهای قدیمی برای سازگاری باقی مانده‌اند. جزئیات در `docs/ARCHITECTURE.md` ثبت شده است.

تست `app-assets-routing` خروجی واقعی توابع PHP افزونه را با بدل‌های WordPress در مرورگر بارگذاری و رفتار ۴۰۴ میزبان را شبیه‌سازی می‌کند. `test:app-assets` قرارداد URL، MIME و فهرست مجاز فایل‌ها را بررسی می‌کند؛ `test:service-worker` مرز کش عمومی/خصوصی را با محیط آزمایشی بررسی می‌کند. این تست‌ها نیز جایگزین نصب و تست WordPress واقعی نیستند.

```bash
npm run package
npm run package:check
```

خروجی در `dist/fandoogh-manager.zip` ساخته می‌شود. سازندهٔ بسته فهرست مجاز مشخصی دارد، فایل‌ها را به‌ترتیب پایدار می‌نویسد و timestamp و permission ثابت استفاده می‌کند؛ بنابراین با سورس یکسان، hash فایل ZIP نیز یکسان است. `package:check` هم فهرست و محتوای هر فایل را با سورس مقایسه می‌کند.

در بسته فقط فایل‌های runtime افزونه، `assets/`، `app/`، `languages/` و راهنمای نصب قرار می‌گیرند. تست‌ها، workflow، ابزارهای توسعه، `package.json`، ZIPهای قبلی و پوشه‌های build عمداً خارج هستند.

برای نصب، ZIP را از مسیر `dist/` در WordPress از بخش «افزونه‌ها → افزودن → بارگذاری افزونه» بارگذاری و سپس فعال کنید. جزئیات نصب کوتاه داخل `package-readme.md` نیز همراه بسته قرار می‌گیرد.

## CI

Workflow موجود در `.github/workflows/playwright.yml` Node 20 را نصب می‌کند، browserهای Chromium و WebKit را با dependencyهای لینوکس نصب می‌کند، lint، تست‌های preview و بررسی بستهٔ نصب را اجرا می‌کند. برای اجرای تست واقعی API یا WordPress باید محیط integration جداگانه تعریف شود؛ preview این نقش را ندارد.
