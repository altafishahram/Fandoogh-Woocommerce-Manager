# Fandoogh Manager

افزونهٔ پایهٔ مدیریت فروشگاه فندوق برای WordPress و WooCommerce است. رابط مدیریت به‌صورت یک PWA بدون وابستگی runtime ارائه می‌شود و اتصال واقعی آن از API داخلی افزونه انجام می‌شود.

## توسعه و بررسی

### صندوق فروش حضوری — ۱٫۴٫۰

در وب‌اپ، «فروش حضوری» کالاها را با تایپ، گفتار فارسی، دوربین یا بارکدخوان USB پیدا می‌کند. فهرست کالاها صفحه‌بندی دارد و محصولات متغیر، انتخاب تنوع مستقل دارند. قیمت هر ردیف فقط برای همان فروش اصلاح می‌شود؛ تخفیف مبلغی/درصدی، مشتری گذری، انتخاب مشتری قبلی و معرفی مشتری جدید هنگام صدور فاکتور پشتیبانی می‌شوند. وجه نقد، رسید کارت‌خوان یا ترکیبی از هر دو همراه باقی‌ماندهٔ نقد و شمارهٔ پیگیری ثبت می‌شوند؛ اتصال مستقیم به سخت‌افزار یا درگاه کارت‌خوان در این نسخه وجود ندارد.

قبل از ثبت، مبلغ و موجودی روی سرور بررسی می‌شود. پس از تأیید دریافت وجه، سفارش WooCommerce با `created_via=fandoogh-pos` پرداخت‌شده و تحویل‌شده ثبت می‌شود و موجودی همان انبار مشترک کاهش می‌یابد. قیمت محصول تغییر نمی‌کند. قطع پاسخ ثبت، صندوق را برای بررسی همان شناسه قفل می‌کند؛ فروش نامشخص هرگز خودکار با شناسهٔ تازه ارسال نمی‌شود.

برای فروش حضوری و سفارش‌های قبلی، دکمهٔ چاپ، پیش‌نمایش A4، A5 و فیش ۸۰ میلی‌متری دارد. مشخصات فعلی فروشگاه/لوگو، مشتری و مبالغ ذخیره‌شدهٔ سفارش خوانده می‌شوند؛ بازپرداخت‌ها هم نمایش داده می‌شوند. در پنجرهٔ چاپ، چاپگر و اندازهٔ کاغذ متناظر را انتخاب و سربرگ/پابرگ مرورگر را خاموش کنید. پشتیبانی اندازهٔ سفارشی به مرورگر و درایور چاپگر وابسته است.

گزارش‌ها فیلتر منبع فروش، مبلغ ناخالص، بازپرداخت و خالص فروش را دارند. سفارش‌های دارای نشان `fandoogh-pos` حضوری‌اند؛ سفارش‌های قدیمی بدون این نشان در «آنلاین و سایر سفارش‌ها» قرار می‌گیرند. بازه بر تاریخ ایجاد سفارش اعمال می‌شود، بنابراین بازپرداخت‌های همین سفارش‌ها محاسبه می‌شوند، نه گردش بازپرداخت به تفکیک تاریخ پرداخت. مبالغ شامل مالیات و ارسال‌اند؛ سفارش‌های `on-hold` نیز مطابق رفتار قبلی گزارش، در مبالغ منظور می‌شوند. خالص فروش به معنای سود یا وجه وصول‌شده نیست.

مجوزهای `products.read`، `orders.read`، `orders.create` و اجازهٔ تغییرات مهم برای صندوق لازم‌اند. معرفی مشتری به `customers.write` و انتخاب مشتری به `customers.read` نیاز دارد. تست‌های `npm run test:pos` و `npx playwright test e2e/pos-workflow.spec.js` از بدل‌های WooCommerce و API استفاده می‌کنند؛ جایگزین بررسی روی نصب واقعی WooCommerce و چاپگر نیستند.

پیش‌نیازها: Node.js 20 یا جدیدتر و PHP برای بررسی syntax فایل‌های backend.

```bash
npm ci
npx playwright install chromium webkit
npm run lint
npm run test:coupons
npm run test:product-categories
npm run test:app-assets
npm run test:service-worker
npm run test:admin
npm run test:analytics
npm run test:e2e:chromium
npm run test:e2e:webkit
```

`npm run test:e2e:preview` (و aliasهای `test:e2e` و `test:e2e:all`) همهٔ پروژه‌ها را اجرا می‌کند. تست‌های چیدمان برنامه را از سرور استاتیک `tools/static-server.js` و با `?preview=1` باز می‌کنند. تست‌های گردش کار کوپن پاسخ‌های HTTP را در مرورگر شبیه‌سازی می‌کنند تا نمایش نتیجهٔ ثبت، صفحه‌بندی و خطاها بررسی شود. `test:coupons` نیز قرارداد backend را با مدل‌های آزمایشی درون حافظه بررسی می‌کند. این آزمون‌ها جایگزین تست integration روی WordPress و WooCommerce واقعی نیستند.

## ساخت بستهٔ نصب

### پنل راه‌اندازی و راهنمای استفاده — ۱٫۳٫۱۷

پنل وردپرس با طرح تأییدشدهٔ پیش‌نمایش هماهنگ شده است: وضعیت واقعی ووکامرس، HTTPS و دستگاه‌های متصل، کادر «راه‌اندازی و عملکرد افزونه» در سه بخش، چهار دسترسی سریع و جزئیات فنی بازشونده. تب‌های اتصال گوشی، دسترسی کاربران و ظاهر وب‌اپ مسیر شروع را روشن می‌کنند؛ فرم‌های کامل فعلی، nonce و ذخیرهٔ مستقل هر تب حفظ شده‌اند. شمارش دستگاه‌ها بر اساس حداکثر ۵۰۰ نشست اخیر است.

راهنما بدون JavaScript هم خواندنی است؛ اسکریپت محلی آن را به تب‌های قابل استفاده با صفحه‌کلید تبدیل می‌کند. در تب اتصال، نشانی واقعی وب‌اپ را می‌توان کپی کرد؛ اگر اجازهٔ Clipboard داده نشود، نشانی برای کپی دستی انتخاب می‌شود. راهنمای رفع مشکل، اتصال، اعلان، دوربین/میکروفون و گزارش مالی را پوشش می‌دهد. کنترل اعلان گوشی در وب‌اپ انجام می‌شود و با ایمیل امنیتی نشست‌ها تفاوت دارد.

`test:admin` قراردادهای تنظیمات، شمارش واقعی و محدودبودن بارگذاری فایل‌ها به صفحات افزونه را بررسی می‌کند. `e2e/admin-panel.spec.js` خروجی واقعی PHP را با بدل‌های وردپرس در مرورگر آزمایش می‌کند؛ نصب/ذخیره در وردپرس واقعی را شبیه‌سازی نمی‌کند. فایل‌های پیش‌نمایش مستقل در `prototypes/` در ZIP نصب قرار نمی‌گیرند.

### هشدار گوشی، بارکد، جستجوی صوتی و کارهای امروز — ۱٫۳٫۱۶

- در همهٔ کادرهای جستجو، دکمهٔ میکروفن برای گفتار فارسی اضافه شده است. پشتیبانی به مرورگر و سرویس گفتار آن بستگی دارد؛ افزونه صدای کاربر را ذخیره نمی‌کند و بعضی مرورگرها پردازش را روی سرویس خود انجام می‌دهند.
- کنار جستجوی کلی، محصول، موجودی و محصولات قیمت‌گذاری گروهی، اسکن بارکد با دوربین پشت گوشی در دسترس است. بارکد باید در SKU یا شناسهٔ جهانی ووکامرس ثبت شده باشد. شناسهٔ جهانی در نسخه‌های دارای API آن پشتیبانی می‌شود؛ SKU روی نسخه‌های قدیمی هم کار می‌کند. ZXing داخل بسته برای مرورگرهای بدون اسکنر بومی موجود است؛ ورود دستی نیز در دسترس است.
- «کارهای امروز» در داشبورد، بررسی پرداخت، ارسال و موجودی کم را با اقدام مستقیم نمایش می‌دهد. تأخیر ارسال بیش از ۴۸ ساعت علامت می‌خورد؛ سفارش‌های مجازی و ارسال‌شده وارد این فهرست نمی‌شوند. موجودی و ارسال صفحه‌بندی دارند؛ شمارش این دو مربوط به صفحهٔ بررسی‌شده است.
- «هشدارهای این گوشی» از داشبورد یا پنل زنگ اعلان باز می‌شود. نوع هشدار و ساعت سکوت برای همان نشست ذخیره می‌شود؛ ساعت سکوت از منطقهٔ زمانی وردپرس استفاده می‌کند. اعلان آزمایشی برای بررسی اتصال موجود است.

دوربین، میکروفن و Web Push به HTTPS و اجازهٔ کاربر نیاز دارند. روی آیفون، وب‌اپ را به Home Screen اضافه و از همان‌جا باز کنید. برای ارسال اعلان، میزبان باید OpenSSL با EC/ECDH و دسترسی خروجی HTTPS به سرویس Push مرورگر داشته باشد. پردازش سفارش و موجودی منتظر ارسال اعلان نمی‌ماند؛ WP-Cron ارسال را انجام می‌دهد و زمان دریافت به اجرای آن و سرویس گوشی وابسته است. اعلان‌ها تا زمانی که نشست و دسترسی معتبرند ارسال می‌شوند. متن اعلان شامل مشخصات مشتری نیست.

`npm run test:operations` مجوزها، بارکد، صفحه‌بندی، ساعت سکوت و رمزنگاری Web Push را بررسی می‌کند. تست مرورگری عملیات، API، دوربین، گفتار و سرویس گوشی را شبیه‌سازی می‌کند؛ دریافت واقعی روی گوشی به نصب و آزمایش روی فروشگاه نیاز دارد.

### پنل مدیریت و گزارش مالی — ۱٫۳٫۸

منوی Fandoogh Manager اکنون یک پیشخوان با هشت تب دارد: پیشخوان، ظاهر، رسانه و فونت، گزارش مالی، دسترسی کاربران، نشست‌ها و امنیت، اتصال و وب‌اپ، رهگیری سفارش. هر فرم فقط کلیدهای مجاز همان تب را با آخرین تنظیمات ذخیره‌شده ادغام می‌کند؛ خاموش‌کردن یک چک‌باکس در یک تب، تنظیمات تب دیگر را تغییر نمی‌دهد. آدرس قدیمی «تنظیمات» همچنان باز می‌شود.

برای گزارش مالی، ابتدا گزینه را در تب گزارش مالی ذخیره کنید. حساب باید مجوز مدیریت ووکامرس یا تنظیمات وردپرس و دسترسی تحلیل در افزونه داشته باشد. اگر کد اتصال/نشست پیش از فعال‌شدن گزارش صادر شده، در «اتصال و وب‌اپ» کد جدید بسازید، از وب‌اپ خارج شوید و دوباره با آن وارد شوید. افزایش خودکار مجوز نشست قدیمی عمداً انجام نمی‌شود. اکنون این وضعیت به‌جای ناپدیدکردن بخش، پیام روشن دارد؛ شکست دریافت دادهٔ ووکامرس نیز با گزارش خالی اشتباه گرفته نمی‌شود.

`test:admin` ذخیرهٔ مستقل تب‌ها و خروجی واقعی توابع PHP را با بدل‌های وردپرس بررسی می‌کند. تست مرورگری پنل، HTML واقعی همین توابع را در قاب سبک‌شدهٔ آزمایشی وردپرس بررسی می‌کند؛ جایگزین تأیید ظاهر/ذخیره روی سایت واقعی نیست. `test:analytics` و تست مرورگری گزارش مالی هم با دادهٔ آزمایشی اجرا می‌شوند.

از نسخهٔ ۱٫۳٫۶، فایل‌های عمومی پوسته با پارامتر `fandoogh_manager_asset` روی مسیر `/manager/` تحویل می‌شوند؛ بنابراین میزبان‌هایی که مسیرهای مجازی `.css` و `.js` را مستقیماً در Nginx با ۴۰۴ پاسخ می‌دهند، نیازی به قانون ویژه برای این فایل‌ها ندارند. مسیر خود `/manager/` باید همچنان در وردپرس قابل دسترسی باشد. مسیرهای قدیمی برای سازگاری باقی مانده‌اند. جزئیات در `docs/ARCHITECTURE.md` ثبت شده است.

تست `app-assets-routing` خروجی واقعی توابع PHP افزونه را با بدل‌های WordPress در مرورگر بارگذاری و رفتار ۴۰۴ میزبان را شبیه‌سازی می‌کند. `test:app-assets` قرارداد URL، MIME و فهرست مجاز فایل‌ها را بررسی می‌کند؛ `test:service-worker` مرز کش عمومی/خصوصی را با محیط آزمایشی بررسی می‌کند. این تست‌ها نیز جایگزین نصب و تست WordPress واقعی نیستند.

```bash
npm run package
npm run package:check
```

خروجی در `dist/fandoogh-manager.zip` ساخته می‌شود. سازندهٔ بسته فهرست مجاز مشخصی دارد، فایل‌ها را به‌ترتیب پایدار می‌نویسد و timestamp و permission ثابت استفاده می‌کند؛ بنابراین با سورس یکسان، hash فایل ZIP نیز یکسان است. `package:check` هم فهرست و محتوای هر فایل را با سورس مقایسه می‌کند.

در بسته فقط فایل‌های runtime افزونه، `assets/`، `app/`، `languages/` و راهنمای نصب قرار می‌گیرند. تست‌ها، workflow، ابزارهای توسعه، `package.json`، ZIPهای قبلی و پوشه‌های build عمداً خارج هستند.

برای نصب، ZIP را از مسیر `dist/` در WordPress از بخش «افزونه‌ها → افزودن → بارگذاری افزونه» بارگذاری و سپس فعال کنید. جزئیات نصب کوتاه داخل `package-readme.md` نیز همراه بسته قرار می‌گیرد.

## CI

Workflow موجود در `.github/workflows/playwright.yml` Node 20 را نصب می‌کند، browserهای Chromium و WebKit را با dependencyهای لینوکس نصب می‌کند، lint، تست‌های preview و بررسی بستهٔ نصب را اجرا می‌کند. برای اجرای تست واقعی API یا WordPress باید محیط integration جداگانه تعریف شود؛ preview این نقش را ندارد.
